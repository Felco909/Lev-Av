# Миграция данных о топливе на единый источник VehicleTrip/Wialon

Дата: 2026-07-24. Коммиты `8175e81` (раздел «Топливо» — исходный фикс, до этой миграции) →
`6aff2c8` (Driver/Vehicle Analytics, Автопарк→Расходы, Себестоимость заявки) → `5500141`
(карточка машины, Excel-экспорт).

## Зачем

После того как раздел «Топливо» (`/fuel`) был переведён на `VehicleTrip`/Wialon
(коммит `8175e81`), полный аудит показал: ещё 4 раздела продолжали читать топливо из старых
источников (`FuelRecord`, `Expense`) — из-за этого «сколько потратили на топливо за месяц»
отличалось в зависимости от того, какой раздел открыть.

## Источник истины (не путать эти два измерения)

- **Расход/эффективность** (литры, л/100км, уровни, заправки/сливы) — только `VehicleTrip`:
  `calculatedFuelConsumedL`, `calculatedKm`, `wialonAvgFuelConsumptionPer100Km`,
  `wialonFuelLevelBeginL/EndL`, `wialonFillingsCount/FilledL`, `wialonTheftsCount/TheftedL`.
  Без фолбэков — если Wialon-отчёт не рассчитан, показывать «—», не оценку.
- **Стоимость (֏)** — только `VehicleTrip.fuelCostAmd`. **`FleetExpense` — отдельный расходный
  поток и никогда не подмешивается в «Топливо»**, даже строки с `expenseType='fuel'`. Это
  конвенция уже существовавшего эталонного отчёта `app/api/reports/own-fleet/route.ts` —
  там `FleetExpense` показывается отдельной таблицей «Расходы автопарка», не суммируется в
  топливный бакет. Первый проход миграции (driver-analytics, vehicle-analytics) по ошибке
  приплюсовывал `FleetExpense(fuel)` к топливу — поймано и откачено до коммита, иначе это
  создало бы новое расхождение вместо устранения старого.
- `FuelRecord` — только ручной журнал «заправки/корректировки» на `/fuel`, нигде в
  аналитике/отчётах/экспорте/себестоимости больше не читается (проверено грепом).

## Переключённые потребители

| Файл | Было | Стало |
|---|---|---|
| `app/api/driver-analytics/route.ts` | `Expense`(fuel, по `Trip`) + `FuelRecord`(по `vehicleId`, косвенная связь через историю заявок водителя) | `VehicleTrip.driverId` напрямую; л/100км — взвешенный Σл/Σкм, не среднее средних |
| `app/api/vehicle-analytics/route.ts` | `FuelRecord`(по `vehicleId`) | `VehicleTrip.calculatedFuelConsumedL`/`fuelCostAmd`, тот же запрос, что уже строил прибыль; добавлен `fuelPer100Km` |
| `app/api/reports/vehicle-expenses/route.ts` (Автопарк→Расходы) | `FuelRecord`, группировка по дате заправки | `VehicleTrip.fuelCostAmd`, группировка по `departureDate` — жёсткий cutover, теперь совпадает с `reports/own-fleet` |
| `app/api/trips/[id]/costs/route.ts` (Себестоимость заявки) | `FuelRecord` за календарный месяц по `vehicleId` — задваивало сумму, если у машины несколько заявок в месяце | `Trip.vehicleTripId` точная связь; полная сумма рейса на каждой заявке с пометкой в UI, если заявок несколько; не привязан — не показываем оценку |
| `app/api/vehicles/[id]/economics/route.ts` (карточка машины) | топлива не было вовсе | добавлены Σл/Σкм/весовое л-100км/Σ`fuelCostAmd` в уже существующий запрос |
| `app/api/reports/trips/xlsx/route.ts`, `app/api/dashboard/xlsx/route.ts` | топливо не экспортировалось | новый лист «Топливо» (дата, № рейса, машина, л, л/100км, ֏) |

**Намеренно НЕ тронуто**: `maintenanceCost` в виджете «Себестоимость заявки» (ТО/ремонт) —
нет связи с `VehicleTrip`, осталась старая месячная эвристика по решению пользователя, вне
периметра этой миграции.

## Проверка

Каждый шаг сверялся вручную (без постоянного скрипта, по явному решению пользователя)
прямым запросом к БД + Playwright-тестом через одноразового QA-пользователя (роль
`director`, удалён после теста) — см. `phase-by-phase-workflow` в памяти агента.
