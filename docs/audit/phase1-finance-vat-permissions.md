## 🔴 CRITICAL

### TMS-AUDIT-0001 — Дашборд и Reports по-разному считают прибыль по своему транспорту
**Раздел:** Отчёты / Финансы
**Функция:** KPI "Прибыль" на странице Reports (вкладка "Обзор") и Excel-экспорт
**Проблема:** `app/api/reports/trips/route.ts` и `app/api/reports/trips/xlsx/route.ts` суммируют сырое поле `Trip.profitAmd` по **всем** типам заявок, включая `own_transport`. Для собственного транспорта `carrierRateAmd`/`carrierExpensesAmd` в этой формуле равны 0 — то есть `profitAmd` там на самом деле **выручка**, а не прибыль (реальные расходы парка — зарплата, суточные, топливо — лежат в `VehicleTrip`, не в `Trip`, и не вычитаются).
`app/api/dashboard/route.ts:336-362` этот же баг уже нашёл и исправил (есть явный комментарий об этом), но фикс не перенесён в `/api/reports/trips` и его Excel-экспорт.
**Как воспроизвести:** Открыть Reports → вкладка "Обзор" за период с заявками по собственному транспорту → сравнить KPI "Прибыль" с суммой из вкладки "Автопарк" (`/api/reports/own-fleet`, которая считает правильно) за тот же период.
**Ожидаемый результат:** Одна и та же прибыль по одним и тем же рейсам.
**Фактический результат:** Числа расходятся на сумму невычтенных расходов парка (зарплата+суточные+топливо+прочее).
**Файл/API:** `app/api/reports/trips/route.ts:99-208`, `app/api/reports/trips/xlsx/route.ts:239-256`
**Причина:** Фикс из `dashboard/route.ts` не распространён на соседний, дублирующий по смыслу код.
**Рекомендация:** Заменить прямое суммирование `Trip.profitAmd` на тот же расчёт, что в `dashboard/route.ts` (expedition — построчно `profitAmd`, own_transport — через `computeOwnFleetTotals`/`getVehicleTripsIncomeAmdBulk` − `computeVehicleTripExpensesAmd`). Затронуты: KPI "Прибыль", месячный график, `vehicleStats`, `topClients`, `lossTrips`, Excel лист "Прибыль".

### TMS-AUDIT-0002 — Массовая переоценка курса ломает ставку перевозчика при разных валютах клиент/перевозчик
**Раздел:** Финансы / Валюты
**Функция:** `POST /api/trips/revalue`
**Проблема:** Эндпоинт находит заявки по валюте **клиента** (`currency`), но применяет новый курс и к `carrierRateAmd` тоже — без проверки `carrierCurrency`. Если у заявки клиент в USD, а перевозчик оплачивается в RUB (это штатный сценарий, форма это явно позволяет), пересчёт курса USD применит курс USD к сумме в RUB.
**Как воспроизвести:** Создать экспедиторскую заявку: клиент — USD, перевозчик — RUB. Выполнить массовую переоценку курса USD. Проверить `carrierRateAmd`/`profitAmd` этой заявки до/после.
**Ожидаемый результат:** `carrierRateAmd` пересчитывается по курсу RUB (или не трогается вовсе).
**Фактический результат:** `carrierRateAmd` пересчитан по курсу USD → неверная AMD-сумма → неверная `profitAmd`, без записи в историю (в отличие от обычного редактирования заявки, `recordTripHistory` здесь не вызывается).
**Файл/API:** `app/api/trips/revalue/route.ts:21-42`
**Причина:** Тот же класс бага, что уже был исправлен для RUB (курс×1), но на другой оси — валюта перевозчика игнорируется.
**Рекомендация:** Фильтровать/пересчитывать `carrierRateAmd` только если `carrierCurrency === currency` пересчитываемой валюты, иначе — отдельный проход по `carrierCurrency`. Добавить запись в `TripHistory`.

### TMS-AUDIT-0003 — `POST /api/trips/revalue` и `PUT /api/exchange-rates` не проверяют роль
**Раздел:** Права доступа / Финансы
**Функция:** Массовая переоценка курса заявок; изменение курсов валют компании
**Проблема:** Оба эндпоинта проверяют только наличие сессии (`if (!session)`), без `assertRole`. Массовая переоценка (TMS-AUDIT-0002) и изменение курсов валют, от которых зависит AMD-эквивалент **каждой новой заявки**, доступны любой аутентифицированной роли, включая dispatcher — хотя точечное редактирование ставки одной заявки диспетчеру разрешено намеренно, здесь по сути можно одним запросом переписать прибыль по всему портфелю или подменить курсы, по которым считается всё остальное.
**Как воспроизвести:** Авторизоваться как dispatcher → `curl -X POST /api/trips/revalue -d '{"currency":"USD","newRate":1}'` или `curl -X PUT /api/exchange-rates -d '{"USD":1}'`.
**Ожидаемый результат:** 403 для ролей вне `CRITICAL_FINANCE_FIELDS_ROLES` (admin/owner/director/accountant).
**Фактический результат:** 200, изменения применяются.
**Файл/API:** `app/api/trips/revalue/route.ts:9-71`, `app/api/exchange-rates/route.ts:23-43`
**Причина:** Пропущен вызов `assertRole` при добавлении эндпоинтов — соседние по смыслу настройки (`app/api/settings/route.ts` для `company_*`) защищены, эти — нет.
**Рекомендация:** Добавить `assertRole(session, CRITICAL_FINANCE_FIELDS_ROLES)` в оба.

### TMS-AUDIT-0004 — Реюз завершённой/архивной заявки без проверки роли и в обход существующего guard-хелпера
**Раздел:** Права доступа / Жизненный цикл заявки
**Функция:** `PUT /api/trips/[id]/close` (reopen-ветка)
**Проблема:** Ветка закрытия (`POST`) корректно проверяет роль для `closeDebts`. Ветка повторного открытия (`PUT`, возврат из "Завершён"/архива в "На оплату"/"Сверка") проверяет только сессию — без роли — и **не использует** уже существующий в кодовой базе `lib/trip-workflow-guards.ts` → `assertReopenToAwaitingPaymentTransition`, а дублирует проверку локально.
**Как воспроизвести:** dispatcher → `PUT /api/trips/[id]/close` на завершённой заявке.
**Ожидаемый результат:** Реюз ограничен ролями, которые могут управлять статусом закрытия (как минимум те же, что закрывают долг).
**Фактический результат:** Любая аутентифицированная роль реоткрывает завершённую заявку и после этого свободно правит `clientRate`/`carrierRate`/расходы/статус через обычный PUT (поля `clientPaidAmount*` по-прежнему защищены).
**Файл/API:** `app/api/trips/[id]/close/route.ts:149-173`, неиспользуемый хелпер в `lib/trip-workflow-guards.ts`
**Причина:** Guard написан, но не подключён к этому route; вероятно забыли при рефакторинге.
**Рекомендация:** Вызвать существующий `assertReopenToAwaitingPaymentTransition` + добавить `assertRole`.

### TMS-AUDIT-0007 — VAT-поле полностью выпадает во втором генераторе документов + DOCX/XLSX без НДС вообще
**Раздел:** Документы / НДС
**Проблема:** Коммит `7673b55` исправил расхождение НДС между счётом и актом **только** в активно используемом пути (`app/api/trips/[id]/generate-docs`). Второй, тоже рабочий (не удалённый) эндпоинт `app/api/documents/generate/route.ts` строит свой `docOverrides` без поля `ndsTax` вообще — при вызове напрямую всегда покажет дефолт "НДС 0%" независимо от реальных данных заявки. DOCX/XLSX-генераторы (`lib/doc-generators.ts`) не имеют понятия НДС в принципе — `grep` не находит ни одного упоминания.
**Как воспроизвести:** `curl -X POST /api/documents/generate` для заявки с ненулевым НДС → сравнить с PDF из штатного UI-потока.
**Файл/API:** `app/api/documents/generate/route.ts:116-135,255-272`, `lib/doc-generators.ts`
**Причина:** Фикс НДС применён к одному из двух параллельных генераторов документов — второй не найден при поиске мест использования `ndsTax`.
**Рекомендация:** Либо удалить неиспользуемый `/api/documents/generate` (проверить, что на него точно никто не завязан — см. открытый вопрос #2), либо прокинуть `ndsTax` туда же и добавить в DOCX/XLSX-шаблоны.

### TMS-AUDIT-0008 — Диспетчер и любая роль могут реоткрыть закрытую заявку (см. TMS-AUDIT-0004) — влияние на бизнес-процесс
Дублирует техническую причину TMS-AUDIT-0004, вынесено отдельно, т.к. напрямую отвечает на пункт ТЗ "проверить невозможность неправильных переходов между статусами". Статусный workflow "На оплату → Сверка → Завершён" не одно­направленный, как задокументировано в CLAUDE.md — по факту разворачивается в обе стороны без ограничения по роли.

## Что уже работает правильно (для полноты)

- `computeTripProfitAmd()` как единая точка истины — соблюдается во всех основных write-путях заявки (`trip-form.tsx`, `app/api/trips/route.ts`, `app/api/trips/[id]/route.ts`).
- Разделение `computeExpeditionProfitAmd`/`computeOwnTransportProfitAmd` в `finance-metrics-service.ts` — намеренное и внутренне согласованное, есть встроенный tripwire (`logTripWriteDrift`) и `validateMetricsAgainstContract`.
- Доход собственного транспорта через `Trip.vehicleTripId` (`own-fleet-income.ts`) — соблюдается во всех проверенных потребителях (dashboard, own-fleet отчёт, vehicle-analytics, economics, day-tasks). Диагностический date-range fallback явно помечен как неиспользуемый в проде.
- Правило "Топливо только из VehicleTrip/Wialon, FleetExpense — отдельно" — соблюдается везде, включая Excel-экспорт.
- Задолженности (`debts-service.ts`) — единая точка истины для client/carrier/supplier debt, используется консистентно во всех потребителях.
- Конвертация валют — единообразна (AMD=1, иначе курс из настроек) во всех проверенных местах записи; исторический баг с RUB×1 не воспроизводится.
- НДС на активном пути документов (invoice+act через `/api/trips/[id]/generate-docs`) — счёт и акт показывают одинаковый НДС после `7673b55`. Это единственный путь, реально используемый из UI.
- Основная модель прав (`role-guard.ts`) — хорошо структурирована, специализированные группы ролей для разных типов операций, а не один общий admin-флаг. Платёжный журнал корректно расширен на dispatcher осознанным коммитом `ca355f3`, без побочного расширения прав на прямые поля `Trip`.
