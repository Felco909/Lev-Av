## Незакоммиченный диф — проверен, безопасен

`lib/document-templates.ts`/`lib/pdf-convert.ts`/`lib/document-templates.test.ts` — два независимых фикса, объединённых в один рабочий диф:
1. Исправление НДС: `ov?.ndsTax || 'НДС 0%'` → `ov?.ndsTax !== undefined ? ov.ndsTax : 'НДС 0%'`. Раньше пользователь не мог оставить поле НДС пустым (пустая строка заменялась дефолтом). Прослежено end-to-end (UI → API → шаблон) — работает корректно. **Тесты: `npx vitest run lib/document-templates.test.ts` — 6/6 пройдено.**
2. `lib/pdf-convert.ts` — не связанный с НДС рефакторинг: `execSoffice` больше не маскирует реальную ошибку soffice (таймаут/сбой конвертации) как `ENOENT` от несуществующего кандидата пути; добавлен "прогретый" профиль LibreOffice (копируется на каждый запрос вместо холодной сборки — ускорение ~40с→~5с).
   - **Риск (не подтверждён, но правдоподобен):** `buildTemplateProfile()` проверяет только существование каталога прогретого профиля (`fs.access`), не его целостность. Если сборка была прервана (kill процесса), каталог может остаться в повреждённом состоянии и переиспользоваться молча — сам код это признаёт комментарием, восстановление только вручную.
   - HTML4-атрибуты в `lib/document-templates.ts` (`border="1" width="100%" bgcolor="..."`) после дифа сохранены полностью — регрессии нет.

Диф можно коммитить — не блокирует остальной аудит.

## 🔴 CRITICAL

### TMS-AUDIT-0031 — Excel/PDF экспорт Dashboard полностью игнорирует выбранный на экране период
**Раздел:** Dashboard / Экспорт
**Функция:** Кнопки "Excel"/"PDF" на Dashboard
**Проблема:** `handleDownloadXLSX`/`handleDownloadPDF` (`app/(app)/dashboard/page.tsx:320-331`) вызывают `/api/dashboard/xlsx` и `/api/dashboard/pdf` **без единого query-параметра**, хотя сама страница использует `appliedFrom`/`appliedTo` для основного запроса `/api/dashboard`. `app/api/dashboard/route.ts:55` фильтрует по `tripDate` только `if (dateFrom || dateTo)` — при отсутствии обоих все расчёты (проблемные заявки, долги, прибыль) идут **по всем заявкам за всю историю**, не за период, который виден на экране.
**Как воспроизвести:** Открыть Dashboard (по умолчанию — текущий месяц), скачать Excel/PDF. Числа в файле разойдутся с видимыми KPI, как только появятся данные вне текущего месяца — и расхождение будет расти каждый месяц.
**Файл/API:** `app/(app)/dashboard/page.tsx:320-331`
**Причина:** Пропущена передача `appliedFrom`/`appliedTo` — соседняя по смыслу кнопка экспорта на странице Reports (`app/(app)/reports/page.tsx:515-521`) делает это правильно.
**Рекомендация:** Прокинуть `dateFrom`/`dateTo` в оба запроса, аналогично Reports.

## 🟠 HIGH

### TMS-AUDIT-0032 — Два PDF-роута нарушают правило "только HTML4-атрибуты для LibreOffice" — таблицы рендерятся без рамок и заливки в реальном PDF
**Раздел:** Документы / PDF
**Проблема:** Известное правило CLAUDE.md (LibreOffice игнорирует CSS `border`/`width`/`background` на `<table>`) соблюдено в `lib/document-templates.ts`, но **не** в двух других местах, которые строят HTML инлайн и тоже прогоняют его через `convertHtmlToPdf()`:
- `app/api/dashboard/pdf/route.ts:22-25,58-60` — `<table>`/`<th>`/`<td>` без HTML4-атрибутов, только CSS `width:100%`, `border-collapse`, `background:#f3f4f6`.
- `app/api/reports/reconciliation/route.ts:68-70,79` — то же самое, причём это клиентский финансовый документ (акт сверки).
**Как воспроизвести:** Сгенерировать Dashboard PDF или акт сверки → открыть PDF (не HTML-превью в браузере) → таблицы без видимых рамок, без заливки заголовков, произвольная ширина колонок.
**Файл/API:** `app/api/dashboard/pdf/route.ts:22-25,58-60`, `app/api/reports/reconciliation/route.ts:68-70,79`
**Причина:** Оба файла — независимые инлайн-HTML-билдеры, не переиспользуют `lib/document-templates.ts`, поэтому конвенция туда не попала.
**Рекомендация:** Заменить CSS-таблицы на HTML4-атрибуты (`border="1" width="100%" bgcolor="..."`), как в `document-templates.ts`.

### TMS-AUDIT-0033 — Реквизиты компании задублированы: DOCX "Заявка перевозчику" не читает те же настройки, что счёт/акт
**Раздел:** Документы / Настройки
**Проблема:** `lib/doc-generators.ts:238-251,508-509` **хардкодит** название/адрес/ИНН/email/телефон компании и оба варианта имени директора (`CR_COMPANY_RU`/`CR_COMPANY_AM`), используется в `carrierRequestDocx` (живой путь, `app/api/documents/generate/route.ts:73`, `app/api/agents/document/route.ts:429`). Это отдельный от `getCompanySettings()`/поля `company_director` в `Setting` источник — тем, что использует `generateInvoiceHtml`/`generateActHtml` (`lib/document-templates.ts:166,170,281,285`). Если админ поменяет реквизиты через Настройки, счёт/акт подхватят новые данные, а "Заявка перевозчику" — нет.
**Файл/API:** `lib/doc-generators.ts:238-251,508-509`
**Рекомендация:** Читать те же реквизиты из `getCompanySettings()`, а не хардкодить константы.

### TMS-AUDIT-0034 — Виджет "Рейтинги" на Dashboard игнорирует период для вкладок "Машины"/"Водители"
**Раздел:** Dashboard
**Проблема:** `loadRankTab` (`app/(app)/dashboard/page.tsx:307-311`): вкладки "Клиенты"/"Перевозчики" корректно передают `dateFrom`/`dateTo`; вкладки "Машины"/"Водители" зовут `/api/vehicle-analytics`/`/api/driver-analytics` **вообще без дата-параметров** — эти эндпоинты структурно не принимают период (подтверждено на бэкенде, findings Фазы 3 — тот же корень, но новое конкретное проявление внутри виджета с явно видимым общим фильтром периода).
**Как воспроизвести:** На Dashboard выставить период "Январь 2026" → применить → открыть "Рейтинги" → "Клиенты" (январь) → переключить на "Машины" (вся история) — один и тот же видимый фильтр периода даёт разный охват в зависимости от вкладки.
**Файл/API:** `app/(app)/dashboard/page.tsx:307-311`, `app/api/vehicle-analytics/route.ts`, `app/api/driver-analytics/route.ts`
**Рекомендация:** Добавить `dateFrom`/`dateTo` в `vehicle-analytics`/`driver-analytics` (см. также TMS-AUDIT-0026 из фазы 3).

## Что уже работает правильно

- AND-комбинация фильтров (период + клиент + тип заявки) — корректно применяется во всех проверенных эндпоинтах (`/api/reports/trips`, `/api/dashboard`, `/api/reports/carrier-ranking`, `debts-service.ts`), ни один фильтр не теряется при комбинировании.
- Консолидированный источник долгов (`/api/debts`) — используется единообразно в `/api/reports/company-debts`, `/api/reports/supplier-debts`, `/api/reports/reconciliation`, без повторной независимой реализации.
- Пустые результаты (0 заявок за период) — везде отображаются как явный `0`/"Нет данных", ни `NaN`, ни падений не найдено (проверено в `report-chart.tsx`, `formatCurrency`, гейджах Dashboard, всех таблицах Reports).
- N+1-паттернов не найдено ни в одном отчётном API — везде батчевая выборка (`findMany`/`groupBy`/`Promise.all`) с агрегацией за один проход по уже загруженному массиву.
- Настоящая server-side пагинация для списка заявок (`app/api/trips/route.ts:91-152`, `take`/`skip` + `count()`) — по комментарию в коде это уже исправленная в прошлом "бутафорская" пагинация, сейчас работает корректно.
- CSV-экспорт Reports (все вкладки) и Fleet Expenses переиспользует те же вычисленные значения, что уже на экране — по построению не может разойтись с UI.
- НДС-фикс в незакоммиченном дифе — сквозной путь проверен, тесты проходят, `lib/document-templates.ts` остаётся полностью совместим с LibreOffice.
- Экспорт XLSX/DOCX через `exceljs`/нативный DOCX API (не HTML) — ограничение LibreOffice-CSS к ним не относится.
- Языковые варианты имени директора в `carrierRequestDocx` — используются корректно (не перепутаны), хотя и через отдельный от счёта/акта механизм (см. TMS-AUDIT-0033).
