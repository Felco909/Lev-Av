# Бизнес-процессы — LevAV TMS

## Компания
ООО «Лев Энд Ав», Ереван, ул. С. Таронци 3/18, ИНН 02248043. ~40-50 сделок/мес, 7 своих машин, маршруты Армения↔Россия↔Грузия/СНГ. Директор: А. Зограбян.

## Два типа заявок

**Собственный транспорт (`own_transport`)** — везёт своя машина/водитель. Доход = ставка клиента. Расход = зарплата+суточные+топливо+прочее+расходы парка по **рейсу** (VehicleTrip), а не по заявке напрямую — заявка должна быть явно привязана к рейсу (`vehicleTripId`), иначе висит в статусе «Ожидает привязки» и не входит в доход/расход, пока не привязана.

**Экспедиция (`expedition`)** — везёт сторонний перевозчик. Доход = ставка клиента, расход = ставка перевозчика. Перевыставляемые расходы (топливо, платные дороги и т.п.) разносятся по стороне через маркер в `Expense.description` (`__carrier__` = расход перевозчика, всё остальное — клиента).

## Жизненный цикл заявки (workflow)

```
new → in_progress → unloaded → awaiting_payment → sverka → completed
                                                              │
                                                    (опционально) → archived
                        в любой момент → cancelled
```

- **new** — заявка создана.
- **in_progress** — в пути.
- **unloaded** — разгружена (обязательна дата разгрузки).
- **awaiting_payment** — выставлены документы, ждём оплату (срок оплаты считается автоматически: дата разгрузки + `Client.paymentTermsDays`, либо вручную, если у клиента срок не задан).
- **sverka** — сверка перед закрытием.
- **completed** — сделка завершена. **Гейт закрытия** (3 условия, все обязательны): (1) клиент оплатил полностью — с учётом перевыставляемых расходов; (2) для expedition — перевозчику оплачено полностью; (3) указан налоговый код.
- **archived** — заявка архивируется отдельным шагом после завершения (не автоматически).
- **cancelled** — сделка не состоялась, из любого статуса; исключается из дохода/прибыли/долгов/аналитики полностью (платежи как исторический факт не обнуляются).

Переход возможен только на соседний шаг вперёд/назад (защита от «прыжков» через несколько статусов), см. `lib/trip-workflow-guards.ts`.

## Оплаты

Каждая заявка накапливает независимый журнал платежей (`Payment`, тип client/carrier). `Trip.clientPaidAmountAmd`/`carrierPaidAmountAmd` и статусы оплаты (`not_paid`/`partially_paid`/`paid`) — **денормализованные, пересчитываются автоматически** из журнала после каждого создания/удаления платежа. Прямая правка этих полей в обход журнала защищена ролью (`admin/owner/director/accountant`).

**Просрочка** — считается только при наличии `paymentDueDate` в прошлом и непогашенном остатке (единая функция `computeOverdueFlag`, без исключений и «эвристик по умолчанию»).

**Кассовый разрыв** — ситуация, когда перевозчику уже заплачено больше, чем получено от клиента (`carrierPaid > clientPaid`). Считается по одной формуле везде (`computeCashGapAmd`), с дедупликацией по id заявки при объединении клиентских/перевозчицких долговых списков.

## Собственный автопарк

Рейс (`VehicleTrip`) — отдельная от заявки сущность: выезд/возврат машины с водителем, с собственным набором расходов (зарплата, суточные до 4 отдельных сумм для многостранового маршрута, топливо, прочее, расходы парка). Несколько заявок могут быть привязаны к одному рейсу. Доход рейса = сумма ставок всех привязанных заявок. Присутствие машины на базе отслеживается автоматически через GPS (Wialon) каждые 5 минут.

## Документооборот

Счёт (`invoiceDocNumber`) и акт (`actDocNumber`) — нумеруются автоматически по клиенту (`Client.lastInvoiceNum`/`lastActNum` + `numberFormat`) либо вручную. Генерация PDF — через локальный LibreOffice (без внешних платных сервисов). Вложения (сканы подписанных документов, счета, акты) — локальное хранилище, привязаны к заявке (`TripAttachment`).

## Роли и права

| Роль | Доступ |
|---|---|
| admin, owner, director, accountant | Полный доступ, включая правку денормализованных полей оплаты |
| dispatcher | Обычная работа с заявками + номера счёта/акта + генерация PDF/DOCX |
| Прочие | Согласно назначенной роли, без доступа к критичным финансовым полям |

## Закупки запчастей

`PartPurchase` — закупка (машина, поставщик, сумма). `PartPayment` — журнал оплат закупки, тот же паттерн денормализации/пересчёта, что и у заявок.
